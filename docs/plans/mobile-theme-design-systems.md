# Plan: Mobile theme design systems (13+ presets)

> Generated by the /plan skill on 2026-06-17. Implementation has **not** started.

## 1. Goal

Expand AppGen Flutter mobile generation from three color presets (`appgen`, `portal`, `cookbook`) to a catalog of **domain-oriented design systems** (Corporate, Cookbook, Modern Glass, Material 3, Apple/iOS, Minimal, Dark Pro, Dashboard, Nature, Luxury, Medical, Education, Gaming) as described in `AppGen_Mobile_Theme_Design_System_Ideas.docx`.

Ship in **phases**: first register presets and emit correct color tokens + wizard/workbook selection (fast win); then add typography, component shape, brightness, and navigation variants so themes feel intentionally designed—not only recolored.

## 3. Proposed approach

**Opinion on the theme list:** The proposed set is strong and matches the docx vision. Keep **`appgen`** (default) and **`portal`** (derive from documentation portal colors when enabled). Add all user-listed presets plus **`terminal`** from the docx (developer aesthetic). Treat **`dashboard`** as a **navigation/layout profile** in Phase 2—not only a color palette—because the docx describes tile home screens and KPI layouts, not just colors.

**Phase 1 (this plan's MVP):** Introduce `MobileThemeCatalog` with metadata (id, display name, description, category) and a `MobileThemeProfile` record holding **color tokens + typography + shape tokens + brightness**. Move preset definitions out of the `FlutterThemeResolver` switch into catalog data (JSON or C# records). `FlutterThemeResolver` becomes a thin lookup + override merge (`MobileThemeSpec.PrimaryColor`, etc.). Update wizard dropdown, workbook list validation, and spec merge to use the catalog. Add unit tests asserting each preset emits distinct `app_theme_config.dart` values.

**Phase 2:** Split `theme.dart.scriban` into a base partial plus per-preset Scriban fragments (or generate `theme_profile.dart` with font families, radii, elevations). Update cookbook preset typography to match Huntress (`Cormorant Garamond` headings). Implement `dark-pro` and `gaming` with `Brightness.dark`. Implement `glass` with translucent surfaces (document Android performance caveat).

**Phase 3 (docx long-term vision):** `targets.mobile.navigation` (`drawer` | `bottom-nav` | `rail` | `dashboard-tiles`), card style variants in `app_widgets.dart.scriban`, animation profiles, FAB variants. **`dashboard` preset forces `dashboard-tiles` navigation** and a KPI tile home screen in generated Flutter output.

### 3.2 Component hardening (lessons from HuntressCookbook-Mobile)

Cross-check AppGen Flutter templates against issues fixed or documented in `HuntressCookbook-Mobile/docs/known-issues-and-lessons.md` and `docs/plans/mobile-ux-and-incremental-updates.md`. These are **not** optional polish — they prevented real UX bugs in production.

| Issue | Huntress symptom / fix | AppGen today | Required fix |
|-------|------------------------|--------------|--------------|
| **Android safe area** | Save button hidden behind system nav bar; fixed with `MediaQuery.paddingOf(context).bottom` on form `ListView` padding (`recipe_form_screen.dart`) | `entity_form_screen.dart.scriban` uses fixed `padding: EdgeInsets.fromLTRB(16, 16, 16, 24)` — **no bottom inset** | Add `bottomInset` padding on all scrollable forms and sticky footers |
| **Button label font** | Cookbook applies serif (`Cormorant Garamond`) to `textTheme`; action buttons must stay **sans-serif** (`Inter`) | `theme.dart.scriban` sets `GoogleFonts.inter` on `FilledButton` / `OutlinedButton` — **good** | Keep `buttonFont` separate from `headingFont` in every preset; never inherit serif on buttons |
| **Missing button themes** | Huntress `theme.dart` only defines `filledButtonTheme`; `TextButton` / `OutlinedButton` fall back to defaults | AppGen has `filledButtonTheme` + `outlinedButtonTheme` but **no `textButtonTheme`** | Add `textButtonTheme`, `disabledButton` styles, and `iconButtonTheme` in generated `theme.dart.scriban` |
| **Accent contrast (cookbook gold)** | White text on gold accent (`#C9A227`) is borderline / fails WCAG on light accents | `foregroundColor: Colors.white` hardcoded on all `FilledButton`s | Add `onAccent` token per preset; compute light-or-dark foreground from accent luminance in `FlutterThemeResolver` |
| **Drawer selected tile** | Gold accent text on gold-tinted row background can be low contrast | `app_drawer.dart.scriban`: selected uses `AppColors.accent` on `accent @ 18%` | Add `onSidebar` / `sidebarSelectedBackground` tokens; validate contrast in catalog tests |
| **M3 ColorScheme override** | `ColorScheme.fromSeed` can override explicit button colors unpredictably | `theme.dart.scriban` uses `fromSeed` then `copyWith` button themes | Build explicit `ColorScheme` from catalog tokens (`primary`, `onPrimary`, `surface`, `onSurface`) |
| **Dark themes** | N/A in Huntress (light only) | No dark branch yet | `dark-pro`, `gaming`, `terminal`: dark scaffold + neon/light accents need `onPrimary` checks |
| **Medical accessibility** | Docx requires large touch targets | Default button padding 12px vertical (~40dp total) | `medical` preset: `minHeight: 48`, larger tap targets in profile |
| **Preview gallery** | N/A | Planned CSS mockup | Preview must show **primary button** with correct `onAccent` text color, not only swatches |

### 3.1 Theme preview gallery (wizard UX)

Add a **live CSS mockup preview** in the AppGen Blazor UI so users can compare themes before generating.

**Where it lives (recommended):**

1. **Project tab** — compact phone-frame preview beside the Mobile theme `<select>`; updates when the selection changes.
2. **Mobile tab** — full **“Theme gallery”** panel: grid of all presets with name, one-line description, and mini phone mockup; clicking a card selects that preset and syncs back to Project/manifest.

**Preview component:** `MobileThemePreview.razor` (+ `MobileThemeGallery.razor` for the grid).

Each mockup renders (~280×520px phone chrome):

- Top app bar + menu icon
- **Dashboard preset:** 2×2 KPI stat tiles + “Recent” list card (forced layout preview)
- **Other presets:** sidebar color strip + sample entity list row + primary button
- Swatches for accent / background / surface at the bottom

CSS uses `style="--theme-accent: #…"` from catalog hex tokens; optional `data-preset="glass"` class for blur/translucent effects in Phase 2.

**Why not embed Flutter:** too heavy for the wizard (SDK, build, iframe). CSS mockup is instant, testable, and stays in sync with catalog data via unit test (`PreviewCssVars_match_catalog_tokens`).

**Optional later:** export static PNG thumbnails per theme at build time for docs/README; not required for v1.


### Alternatives considered

- **Only add colors, keep one `theme.dart`** — Rejected for Phase 2+; docx explicitly requires typography, cards, and navigation differences; a single template cannot express Glass vs Minimal vs iOS.
- **External Dart theme package consumed by generated apps** — Rejected for now; AppGen today inlines generated code; package extraction is a separate initiative.
- **Implement all 13 themes with full navigation/animation in one PR** — Rejected; too large, hard to test, blocks shipping incremental value.

## 5. Implementation steps

3. Refactor `FlutterThemeResolver` to resolve via catalog; keep `portal` special-case that merges `spec.Portal.Settings.Theme` overrides.
4. Add preset validation helper (`MobileThemeCatalog.NormalizePreset`) used by spec loader, workbook merger, and wizard.
5. Replace hardcoded theme `<select>` options in `ProjectWorkspace.razor` with catalog-driven options (display name + hint text).
6. Update `SpecWorkbookLists.MobileThemePresets` and workbook validation to match catalog ids.
7. Add `MobileThemeCatalogTests` (all ids registered, no duplicate ids, required token fields present).
8. Extend `MobileGenerationServiceTests` with at least one test per preset family (light: `corporate`, dark: `dark-pro`, existing: `cookbook`).
9. Add `MobileThemePreview.razor` — phone-frame mockup bound to `MobileThemeCatalog.GetProfile(preset)` CSS variables.
10. Add `MobileThemeGallery.razor` on the Mobile tab — clickable grid; selection writes `MobileThemePreset` via `WizardStateService`.
11. Wire inline preview into `ProjectWorkspace.razor` next to the theme dropdown (updates on `@bind:after`).
12. Add `onAccent` / contrast helper in `FlutterThemeResolver`; emit `onAccent` in `app_theme_config.dart.scriban`.
13. Fix `entity_form_screen.dart.scriban` — apply `MediaQuery.paddingOf(context).bottom` to form list padding (Huntress safe-area pattern).
14. Expand `theme.dart.scriban` — explicit `ColorScheme`, `textButtonTheme`, disabled button styles; never serif on buttons.
15. Add `MobileThemeContrastTests` — assert WCAG AA contrast for `accent`/`onAccent` and drawer selected states per preset.

### Phase 2 — Typography, shape, brightness

16. Extend `MobileThemeProfile` with `headingFont`, `bodyFont`, `cornerRadius`, `cardElevation`, `useMaterial3Defaults`, `brightness`.
17. Update `FlutterGenerator` and `app_theme_config.dart.scriban` to emit profile metadata constants.
18. Refactor `theme.dart.scriban` to apply fonts/radii/brightness from profile (cookbook → Cormorant Garamond like Huntress).
19. Add dark-theme branch for `dark-pro` and `gaming` (explicit dark `ColorScheme`, not `fromSeed` only).
20. Add `glass` surface styling (semi-transparent cards, higher blur on supported platforms) in `theme.dart.scriban` + `app_widgets.dart.scriban`.
21. Extend preview CSS for dark themes, glass blur, M3 larger radii, dashboard KPI tiles, and **sample primary button** with correct label contrast.
22. Update `app_drawer.dart.scriban` to use `sidebarSelectedBackground` / `onSidebar` tokens instead of raw accent alpha.

### Phase 3 — Navigation & motion (follow-up plan)

23. Add `MobileNavigationSpec` to `MobileTargetSpec` (`drawer`, `bottom-nav`, `rail`, `dashboard-tiles`).
24. Add `app_shell.*.scriban` variants and select in `FlutterGenerator`; **`dashboard` preset auto-sets navigation to `dashboard-tiles`**.

## 6. Risks & mitigations

- **Risk:** Themes look too similar if only colors change in Phase 1.
  **Mitigation:** Ship Phase 1 with clear UI labels (“colors only until typography update”); prioritize Phase 2 for `ios`, `minimal`, `luxury`, `glass`.
- **Risk:** `glass` / blur hurts performance on low-end Android.
  **Mitigation:** Gate blur behind `Theme.of(context).platform` checks; fallback to opaque surfaces.
- **Risk:** Unknown preset in old `appgen.json` breaks generation.
  **Mitigation:** `NormalizePreset` falls back to `appgen` and logs warning in CLI/UI.
- **Risk:** Google Fonts network dependency at runtime.
  **Mitigation:** Keep existing `google_fonts` pattern; document offline font bundling as future improvement.
- **Risk:** Regenerating existing apps overwrites hand-tuned `theme.dart` (e.g. Huntress).
  **Mitigation:** Document that themes apply at generation time; Huntress remains hand-maintained unless re-imported.

## 7. Testing strategy

- **Unit tests:** `MobileThemeCatalogTests` — catalog size, id uniqueness, portal/cookbook token snapshots.
- **Contrast tests:** `MobileThemeContrastTests` — `onAccent` vs `accent` ≥ 4.5:1 for light presets; cookbook/luxury gold presets included.
- **Generation tests:** `MobileGenerationServiceTests` — generate Flutter app per preset; assert `app_theme_config.dart` contains expected accent hex, `onAccent`, and `preset = '…'`.
- **Workbook tests:** Import/export round-trip with each `MobileThemePreset` value (if workbook tests exist; else add one in `SpecWorkbook` test file).
- **Manual checks:** Generate sample app with `corporate`, `dark-pro`, `glass`, `ios`, `cookbook`; run on **physical Android device with gesture nav** — confirm Save/Create button fully visible above system bar on entity form.
- **Preview UI:** Change theme on Project tab — inline mockup shows primary button with readable label color; select `dashboard` — KPI tile layout visible.
- **Data / migration:** No DB migration. `appgen.json` schema unchanged (preset string widens); old values `appgen`/`portal`/`cookbook` remain valid.
